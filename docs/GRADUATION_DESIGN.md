# 《记忆漂移：最后一个下午》毕业设计说明

## 1. 项目定位

《记忆漂移：最后一个下午》是一件结合互动叙事、网页游戏与实体输入装置的数字媒体艺术作品。观众以“寻忆者”的身份进入编号为 `MEMORY ARCHIVE 07` 的校园记忆档案，通过移动、扫描、压力保持、过载读取、路线选择和碎片重组，形成一个无法被证明为“原始版本”的记忆结果。

作品不把照片、聊天记录或云端数据等同于完整记忆，而是把“回忆会被当前观察者重新组织”转化为可操作的系统规则。

## 2. 核心研究问题

1. 当操作本身改变叙事证据时，玩家是否仍会相信自己选择的版本？
2. 压力输入能否同时承担操作技巧、叙事隐喻和风险反馈三种作用？
3. 在没有失败和死亡的游戏中，空间回环与证据矛盾能否维持探索动机？

## 3. 设计目标

- 单次体验约 4 分钟，适合展览现场快速理解与重复体验。
- 不依赖长篇文字，通过即时视觉、声音和空间反馈表达概念。
- 所有矛盾来自固定故事素材池，避免无意义随机生成。
- 不公布标准答案，使 Version A 与 Version B 始终保持同等合法性。
- 软件输入与硬件输入解耦，便于后期接入摇杆、USB HID 和压力传感器。

## 4. 完整流程

| 阶段 | 主要操作 | 叙事作用 | 预计时间 |
| --- | --- | --- | --- |
| 待机吸引 | 移动方向键 | 观众接入档案 | 循环 |
| 操作校准 | 移动、短按、稳定按住 | 教会扫描与压力 | 15 秒 |
| Stable Archive | 定位并读取 3 个锚点 | 建立“可信记忆” | 45 秒 |
| Memory Drift | 三轨移动、扫描、闪避 | 让空间开始漂移 | 60–75 秒 |
| 三扇门 | 选择空间坐标 | 形成路线偏向 | 10 秒 |
| Corrupted Classroom | 校准时间、地点、人数 | 明确受控矛盾 | 50 秒 |
| Reconstruction | 重新解释 5 块碎片 | 把玩家变成记录者 | 40 秒 |
| Version A/B | 比较并保存 | 暴露版本的不确定性 | 20 秒 |
| 结局反思 | 查看本次操作痕迹 | 回到核心问题 | 10 秒 |

## 5. 压力交互模型

| 区间 | 键盘模拟 | 画面反馈 | 系统影响 |
| --- | --- | --- | --- |
| UNSTABLE 0–30% | 短按或未稳定 | 模糊、漂移 | 只能定位或发出扫描波 |
| FOCUS 30–70% | 稳定按住 0.65–2.3 秒 | 减速、对焦 | 完整读取线索，增加稳定读取次数 |
| OVERLOAD 70–100% | 按住超过 2.3 秒 | 复制、重影、错位 | 强制读取，降低可信度并增加篡改痕迹 |

压力不是“正确/错误按钮”。稳定读取更可靠，过载读取更快速，但两者都会继续推进游戏并参与最终版本计算。

## 6. 记忆偏向系统

系统持续记录以下行为：

- 左右轨道移动；
- 稳定读取与过载次数；
- 是否进入空白数据区；
- 对错误人物的避开、扫描或穿过；
- A-307、B-307 或缺失门牌；
- 时间、地点和人数的校准结果；
- 五块碎片最终采用的解释。

这些行为形成 `memoryBias`。该数值只用于描述玩家的操作轨迹和默认展示顺序，不会宣布真相。玩家仍可在结局自由切换和保存任一版本。

## 7. 视觉与声音语言

- 颜色：米白、雾灰、灰蓝、低饱和淡紫，褪色黄色用于时间标记。
- 图像：旧照片、透明档案层、撕裂空白、人物与椅子残影。
- 空间：二维照片分层后展开为 2.5D 三轨走廊，再折回循环教室。
- 声音：程序化雨声、旧教室环境、时钟、脚步、档案提示音和“等我一下……”短语音。
- 原创性：当前版本的照片、场景、纹理、物件和声音均由程序生成，不复制商业游戏素材。

## 8. LOOT 的实际运用

LOOT 被定位为“交互概念快速验证与展示平台”，不是唯一运行环境。

1. 使用深度创作提示词生成竖屏梦核档案的早期交互草模。
2. 使用“粘贴代码直接预览”导入 `loot/index.html`，验证扫描框、三段压力和三轨收集是否易懂。
3. 根据 LOOT 预览和用户测试反馈修改正式项目。
4. 正式版本在 GitHub 中保留模块化源码、版本记录和自动检查，避免平台生成结果成为不可维护的黑箱。

这种分工更符合毕业设计：LOOT 体现 AI 辅助原型方法，GitHub 体现独立开发、可维护性与过程可追溯性。

## 9. 技术结构

## 10. 用户测试与评价指标

每次完成体验后可按 `E` 导出匿名 JSON 记录，内容只包含本次操作，不包含姓名、账号或设备身份。

建议至少完成 12–20 人次测试，观察：

- 是否能在 15 秒内理解移动、扫描和聚焦；
- 首次完成所需时间；
- 稳定读取与过载读取比例；
- 空白区进入次数；
- Version A/B 的最终选择分布；
- 玩家是否能用一句话说明“数据持久不等于记忆完整”。

## 11. 实体装置接入边界

当前阶段不包含外壳、CAD 和具体传感器接线。未来硬件只需要把摇杆与压力数据转换为统一输入事件：

- `left/right/up/down`
- `pressure-start`
- `pressure-end` 与持续时间

游戏逻辑、画面和叙事无需因硬件更换而重写。
