# LOOT 原型工作流

## 当前里程碑：完整 Web Input 流程

`loot/index.html` 是纯网页完整流程验证版。当前不模拟压力百分比，也不区分空格短按、长按和过载：方向键或 WASD 负责移动与选择，空格键负责探测、对齐、确认或保存，`M` 负责静音，`R` 负责重置。目标是证明玩家不使用鼠标和外接硬件也能完成以下流程：

待机唤醒 → 第一关 3 个扫描锚点 → 第二关三轨移动与 2 个碎片 → 三扇门选择 → 循环教室 3 个坐标 → 5 碎片重组 → Version A/B → 结局 → 自动重置。

2026-08-25 已在 LOOT 预览中实际跑通完整流程：选择 B-307，第三关校准 17:42、B-307、1 人，碎片采用混合解释，最终保存 Version B；结局 10 秒后成功返回待机。测试发现并修复了自动重置后残留结局提示的问题。压力传感器作为未来输入层保留在正式工程设计中，不纳入本里程碑验收。

### Visual Art V2

第二轮优化加入三张原创生成式场景背景：雨天档案教室、三轨记忆走廊和循环教室。素材经过人工筛选、裁切与 WebP 压缩，并嵌入 LOOT 单文件版本，因此离线打开仍能显示。界面由普通系统面板改为旧档案编辑风格，增加衬线标题、竖排档案编号、胶片扫描线、雨幕、漂尘、视差重影和章节转场。

玩法同步改造：走廊扫描会短暂显示真假回声和隐藏轨迹；循环教室需要在移动标记进入黄色窗口时锁定坐标；碎片重组改为方向键控制的九宫格空间拼合，每枚碎片具有两个有效接口。2026-08-25 已在 LOOT 中重新完成从待机到 Version B 的整轮试玩，未发现游戏脚本错误。

### Experience V3

第三轮针对“标题字体像默认网页、玩法按一下就结束”的问题重构：中文任务标题取消英文斜体，改用宋体类档案标题、等宽微标注和黄色分隔线；顶部加入六阶段进度、声音按钮和更明确的状态反馈。第一关每个锚点改成“发现 → 发出探测波 → 在黄色共振区锁定”，第二关下键可进入 1.2 秒聚焦减速，门前会显示矛盾证据表，Version A/B 阶段下键可以打开本轮证据层。

声音全部由 Web Audio API 程序生成，不依赖网络音频文件：包含循环雨声、低频环境底噪、双击时钟、左右声道脚步、扫描和校准提示。2026-08-25 已在 LOOT 重新从待机跑到 Version B，验证五枚碎片、三坐标、五块拼图、证据层和结局均可到达，非浏览器扩展脚本错误为 0。

### Experience V4

V4 不增加装置导入页，仍由待机照片通过任意方向键直接唤醒档案。三轨走廊改为非匀速推进：起步缓慢、随纵深逐渐加速，并叠加轻微呼吸式速度波动；上键触发约 1.15 秒 MEMORY SURGE，下键触发 FOCUS 慢行。界面用三段式 DRIFT PACE 指示当前节奏，不展示复杂速度数值。

玩家角色由几何占位替换为原创“寻忆者 07”背影贴图：旧校服领、档案员外套、褪色黄色吊牌、照片乳剂破损边缘和半透明重影。走廊根据速度状态同步改变跑动起伏、运动残影、脚步节奏和纵深光线。

每个玩法阶段首次进入自动显示 6–8 秒键位教学，H 可重复查看。L 在中文与英文界面间即时切换，标题、提示、面板、按钮说明与结局内容同步变化；F 全屏，M 静音。四段克制的思念叙事短句随走廊进度出现，使主题从“档案故障”进一步落到“是否真的有人陪伴过我”的记忆与遗忘体验。按首次游玩观察节奏，完整流程约 5–6 分钟。

## 项目中的定位

LOOT 用于快速验证交互概念、视觉气氛和展览现场理解成本。正式版本仍保留在模块化源码中，以便后续接入硬件、测试和维护。

## 方法一：直接导入代码

1. 打开 LOOT 首页。
2. 选择“粘贴代码直接预览”。
3. 复制 `loot/index.html` 的完整内容。
4. 粘贴并生成预览。
5. 使用方向键和空格测试扫描、三轨移动、坐标校准、碎片重组、A/B 保存和自动重置。

## 方法二：深度创作

选择“深度创作”，粘贴 `loot/prompt.md` 中的提示词。生成后重点检查：

- 是否保持 1080×1920 竖屏；
- 是否避免霓虹赛博朋克和恐怖人脸；
- 空格键只执行单次扫描，不出现压力百分比或长按判定；
- 是否能在 10–15 秒内理解基本操作；
- 漏掉走廊碎片时是否回环且不会 Game Over；
- 是否能在收齐 5 枚碎片后到达三扇门。
- 循环教室的三个坐标是否能分别选择与确认；
- 五枚碎片是否都能切换双重解释并放置；
- Version A/B 是否同步改变人物、椅子、时间和拍摄方式；
- 保存后是否展示反思结局并在 10 秒后清理界面、返回待机。
- 新背景是否保持文字和白色寻忆者轮廓可读；
- 时间对齐与九宫格拼合是否增加操作变化，同时不会形成 Game Over。

## 迭代记录要求

每轮 LOOT 原型保留：

- 使用日期与提示词版本；
- 首页和关键交互截图；
- 发现的问题；
- 对正式代码的修改；
- 修改后的验证结果。

答辩时不要只展示“使用了 AI 平台”，而要说明 LOOT 具体帮助验证了什么，以及哪些生成结果被人工否决或重新设计。
