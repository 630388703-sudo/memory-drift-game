# LOOT 原型工作流

## 当前里程碑：Web Input First

`loot/index.html` 是纯网页、前两关验证版。当前不模拟压力百分比，也不区分空格短按、长按和过载：方向键或 WASD 负责移动，空格键负责单次扫描或收集，R 键负责重置。目标是先证明玩家不使用鼠标和外接硬件也能完成以下流程：

待机唤醒 → 第一关 3 个扫描锚点 → 第二关三轨移动与 2 个碎片 → 三扇门选择 → 前两关完成。

2026-08-25 已在 LOOT 预览中实际跑通上述流程，选择入口为 B-307；浏览器控制台未发现游戏运行错误。压力传感器作为未来输入层保留在正式工程设计中，不纳入本里程碑验收。

## 项目中的定位

LOOT 用于快速验证交互概念、视觉气氛和展览现场理解成本。正式版本仍保留在模块化源码中，以便后续接入硬件、测试和维护。

## 方法一：直接导入代码

1. 打开 LOOT 首页。
2. 选择“粘贴代码直接预览”。
3. 复制 `loot/index.html` 的完整内容。
4. 粘贴并生成预览。
5. 使用方向键和空格测试扫描、三轨移动、碎片收集和三扇门选择。

## 方法二：深度创作

选择“深度创作”，粘贴 `loot/prompt.md` 中的提示词。生成后重点检查：

- 是否保持 1080×1920 竖屏；
- 是否避免霓虹赛博朋克和恐怖人脸；
- 空格键只执行单次扫描，不出现压力百分比或长按判定；
- 是否能在 10–15 秒内理解基本操作；
- 漏掉走廊碎片时是否回环且不会 Game Over；
- 是否能在收齐 5 枚碎片后到达三扇门。

## 迭代记录要求

每轮 LOOT 原型保留：

- 使用日期与提示词版本；
- 首页和关键交互截图；
- 发现的问题；
- 对正式代码的修改；
- 修改后的验证结果。

答辩时不要只展示“使用了 AI 平台”，而要说明 LOOT 具体帮助验证了什么，以及哪些生成结果被人工否决或重新设计。
